## Summary

Roadmap entry 002 anticipated a GitHub Actions workflow with per-CLI binary installation steps
that invoke the extractor and auto-commit schema JSON. The actual spec and implementation took
a more sophisticated, fully config-driven approach: a new `extractor/obtain.py` generic
downloader, `extractor/refresh.py` orchestrator, and an `obtain` block added to every
registration YAML. The workflow calls `python -m extractor.refresh` instead of per-CLI shell
steps. This is positive scope evolution — the implementation more completely satisfies C-03
(config-driven, no code changes per new CLI) than the matrix-strategy approach the roadmap
anticipated. No governing constraints are violated and all scope-out items remain excluded.
